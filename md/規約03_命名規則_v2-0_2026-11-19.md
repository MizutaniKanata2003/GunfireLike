# GunfireLike 命名規則（規約 3/3）

版: 2.0  
更新日: 2026-11-19 JST  
用途: 識別子・ファイル名の命名を定める。運用手順は「規約01_運用ルール」、整形・コメント・構造は「規約02_コーディング規約」を参照する。節番号は旧v1-2の第4章の節番号をそのまま使用する。

## 1. 基本表記

- アッパーキャメルケース: 単語の先頭を大文字にして連結する。例: SceneManager
- ローワーキャメルケース: 最初の単語を小文字で始め、後続単語の先頭を大文字にする。例: deltaTime
- アッパースネークケース: 単語を大文字で記述し、アンダースコアで区切る。例: PURCHASE_RESULT
- スネークケース: 原則として小文字の単語をアンダースコアで区切る。例: remaining_time
- 略語については第3節の大文字維持規則を優先する。

## 2. 命名一覧

| 対象 | 規則 | 例 |
|---|---|---|
| クラス名 | アッパーキャメルケース | SceneManager |
| 関数・メソッド名 | アッパーキャメルケース | GetCurrentHP |
| 構造体名 | アッパースネークケース | SHOP_UPGRADE_DATA |
| 列挙型名 | アッパースネークケース | PURCHASE_RESULT |
| クラスのメンバー変数 | m_ + ローワーキャメルケース | m_currentHP |
| ローカル変数 | スネークケース | current_HP |
| 通常の関数引数 | ローワーキャメルケース | deltaTime、maxHP |
| 列挙子 | e_ + アッパースネークケース | e_MAX_HP_UPGRADE |
| 構造体のフィールド | ローワーキャメルケース | currentHP |
| 名前付きnamespace | アッパースネークケース（接頭辞なし） | SHOP_MESSAGE |
| namespace内の定数 | ns_ + アッパースネークケース | ns_DISPLAY_DURATION_SECONDS |
| 型エイリアス | アッパーキャメルケース | SceneOwner |
| 型を受け取るテンプレート仮引数 | T + アッパーキャメルケース | TValue、TScene |
| 数値などを受け取るテンプレート仮引数 | アッパースネークケース | ELEMENT_COUNT |
| ファイル名の本体部分 | アッパーキャメルケース | ShopUpgradeData.h |
| 通常の名前付き定数 | アッパースネークケース | MAX_STAGE_COUNT |
| 定数メンバー | m_ + アッパースネークケース | m_MAX_HP |

### 適用区分

- 通常のクラスメンバーにはm_を付ける。
- 通常の構造体フィールドにはm_を付けない。
- 定数メンバーには、通常のメンバー変数・フィールドとは別に定数メンバー規則を適用する。
- 型名とファイル名は別の規則である。構造体SHOP_UPGRADE_DATAのファイル名はShopUpgradeData.hとなる。
- 名前付き・匿名namespace内の定数にはns_を付ける。namespace名自体にはns_を付けない。
- ns_はnamespace内の定数に対する規則であり、内部の関数・型・通常変数すべてへ付ける指示ではない。
- クラス内の定数メンバーは、クラスがnamespace内にある場合もm_ + アッパースネークケースを維持する。
- constであることだけで、用途が通常のローカル変数から定数定義へ変わるわけではない。計算・取得結果を保持するconstローカルはローカル変数規則に従う。

## 3. 略語

略語は通常の大文字・小文字規則より優先し、すべて大文字にする。

例: HP、UI、GPU、FPS

| 対象 | 例 |
|---|---|
| メソッド | GetCurrentHP |
| クラスメンバー | m_currentHP |
| ローカル変数 | current_HP |
| 関数引数 | maxHP |
| 構造体フィールド | currentHP |
| 定数メンバー | m_MAX_HP |
| ファイル | GameUI.h |

略語から始まる場合も大文字を維持する。例: m_UIRenderer、UI_state、UIRenderer.h。

## 4. bool

boolは対象ごとの表記規則に加え、意味に応じてis、has、can、should、didなどを使う。

| 意味 | 例 |
|---|---|
| 現在の状態 | isActive |
| 所有・存在・実行済み | hasTarget |
| 実行可能 | canInteract |
| 実行すべきか | shouldDraw |
| 今回発生した結果 | didHitPlayer |

| 対象 | 例 |
|---|---|
| クラスメンバー | m_isActive |
| ローカル変数 | is_active |
| 関数引数 | isActive |
| 構造体フィールド | didHitPlayer |
| メソッド | CanInteract |

接頭辞は機械的に選ばず、状態・可能性・処理結果の違いが伝わる名前にする。

## 5. 記述例

### 列挙型・構造体

```cpp
// 購入結果の表示状態を表す。
enum class PURCHASE_RESULT
{
  e_NONE,    // 購入結果を表示しない。
  e_SUCCESS, // 購入成功を表示する。
  e_FAILURE  // 購入失敗を表示する。
};

// PlayerのHP表示に必要な状態を保持する。
struct PLAYER_HP_STATE
{
  // 現在のHP。
  float currentHP{};
  // 最大HP。
  float maxHP{};
  // 低HP表示を行うか。
  bool isLowHP{};
};
```

### namespace・定数

```cpp
// 購入結果メッセージの表示に使用する定数をまとめる。
namespace SHOP_MESSAGE
{
  // 購入結果を表示する標準時間。単位は秒。
  constexpr float ns_DISPLAY_DURATION_SECONDS = 1.5f;
}
```

### クラス・メンバー・引数・ローカル

```cpp
// 購入結果の表示状態と表示時間を管理するクラス。
class PurchaseMessage
{
public:
  //========= 更新関数=========
  // 残り表示時間を更新する。
  // deltaTime: この更新で進める経過時間。単位は秒。
  void Update(float deltaTime)
  {
    // 今回の経過時間を引き、終了後の残り時間が負にならないよう制限する。
    const float remaining_time = m_remainingTime - deltaTime;
    // 計算結果が正の間だけ残り時間を保持し、終了後は0へ戻す。
    m_remainingTime = remaining_time > 0.0f ? remaining_time : 0.0f;
  }

private:
  //========= 購入結果表示状態=========
  // 現在表示する購入結果。
  PURCHASE_RESULT m_purchaseResult{PURCHASE_RESULT::e_NONE};
  // 購入結果を表示する残り時間。単位は秒。
  float m_remainingTime{};

  //========= 表示設定定数=========
  // 購入結果を表示する標準時間。単位は秒。
  static constexpr float m_DISPLAY_DURATION_SECONDS = 1.5f;
};
```

### 型エイリアス・テンプレート仮引数

以下の例では、使用する標準Headerなどは省略する。

```cpp
// Sceneの所有権を保持するポインター型の別名。
using SceneOwner = std::unique_ptr<IScene>;

// 指定された型と要素数の固定長配列を表す別名。
// TValue: 配列に格納する要素の型。
// ELEMENT_COUNT: 配列の要素数。
template<class TValue,std::size_t ELEMENT_COUNT>
using FixedArray = std::array<TValue,ELEMENT_COUNT>;
```

## 6. 適用・移行方針

- 今後の新規・変更コードと、コーディング規約文書へ反映する。
- 既存リポジトリー全体へ適用済みであることを意味しない。
- 現状確認中に既存コードを一括改名しない。
- 改名は、宣言・定義・呼び出し・関連ファイルなどの参照と影響範囲を確認し、別タスクとして行う。
- 匿名namespaceは、命名のためだけに名前付きnamespaceへ変更しない。
- 外部ライブラリやWindows APIなど、本プロジェクトが定義しない識別子を本規約へ合わせて改名しない。
- 本書は命名規則をまとめる。整形、コメント、責務、所有権、検証手順の詳細はコーディング規約側で管理する。
