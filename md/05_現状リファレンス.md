## 1. 現在地
現行ゲームは、3D Shopで能力を購入し、各ステージの敵1体を倒して全5ステージを進むソロFPSの基盤。
今回企画した「3部屋×2ウェーブ、3サイクル、3ボス、周回、武器2丁、特殊強化9種」は完成目標であり、現行実装済みではない。

### 環境
|項目|現状|
|---|---|
|API/言語|DirectX 11 / C++20 / HLSL|
|Toolset|提示vcxprojはv145|
|ウィンドウ|初期1280×720、可変サイズ|
|UI|Quad/SpriteFont主体。Debug UIとFadeはImGui|
|音声|DirectXTK Audio|
|3D|Cube、OBJ（位置+UV、任意Texture、単色Tint）|
|Shader|x64 Debug/ReleaseはSM5.0|
|起動対象|slnx→同階層GunfireLike.vcxproj|

## 2. フォルダーと責務
```text
Source/
  main.cpp                       Window・寿命・ループ
  Debug/                         仮プレイヤー移動
  Framework/
    2D/                          Canvas・HUD・Text・Fade
    3D/                          Cube・OBJ Renderer
    Audio/                       AudioSystem
    DirectX/                     Graphics・Buffer・Shader/Texture Loader
    Etc/                         Config・Timer・Logger・MathTypes・GameObject
    Imgui/                       ImGui backend管理
    Input/                       InputSystem・FpsCamera
  Scene/
    Common/                      進捗・戦闘・表示・Gate等
    TitleScene/ ShopScene/ GameScene/ ResultScene/
```
基本はH/とCPP/に分かれる。Source/Framework/Shaders/はHLSL。

## 3. 所有・依存関係
```text
WinMain
├─ GraphicsSystem ─ GPU主要リソース
├─ InputSystem ─ Window非所有
├─ AudioSystem ─ Impl ─ Engine/SoundEffect/Instance
├─ GameTimer
├─ ImGuiManager
└─ SceneManager
   ├─ Current / Next : unique_ptr<IScene>
   ├─ GameProgress : 値
   ├─ FadeOverlay : 値
   └─ Input/Graphics/Audio : 非所有ポインター

各Scene
├─ SceneManager/Input/Graphics/Audio : 非所有参照
├─ Renderer/Component : 値所有
└─ Renderer内部GPU : ComPtr、Text内部 : unique_ptr
```
Framework Systemの寿命はSceneより長い。ゲーム進捗はSceneManagerに同居しており、現状のSceneManagerをゲーム非依存の汎用Managerと表現しない。
Controllerは多くが結果値を返す。GameSceneがHP適用、通貨、SE、Scene遷移等を調停する。

## 4. 起動・フレーム・終了
### 起動
COM MTA → Window登録/生成 → Graphics → Input → Audio → WindowContext登録 → Timer → ImGui → Window表示 → SceneManager → Title。
### フレーム
メッセージ処理 → Timer → Input → Audio → Escape終了確認 → SceneManager.Update → Graphics.BeginFrame → ImGui.BeginFrame → SceneManager.Draw → ImGui.EndFrame → Graphics.EndFrame。
### 通常終了
SceneManager.Finalize → ImGui.Uninit → WindowContext解除 → Input.Uninit → Audio.Uninit → Graphics.Uninit → Window/クラス解除 → COM終了。
明示終了後にもローカル値のデストラクターが動く。二重終了・失敗経路の検証とは別に読む。
### メッセージ
入力はInputSystemへ転送。非Capture時のみImGui handlerへ転送。WM_SIZEはGraphics.Resize、WM_DESTROYは終了要求。

## 5. Sceneライフサイクル
ISceneはInitialize（浅い準備）/Init（失敗可能なResource生成）/Update/Draw/Finalize。
RequestSceneChangeは要求時に次Sceneを構築して予約。Update停止のFadeOut後、黒画面で次Scene.Initialize/Init。
成功後に旧Scene.Finalize→破棄→次Sceneへ移行しFadeIn。失敗時は次Scene.Finalizeし、旧Sceneを保持してFadeIn。
FadeIn/Out中はScene.Updateを止めるが描画と上位Input/Audio更新は継続する。
失敗時の旧Scene保持は、BGM/CaptureやGameProgressの復元を保証しない。

## 6. 現行ゲームの流れ
```text
Title --Enter/新規初期化--> Shop --Challenge Gate--> Game
  ^                         ^                       |
  |                         |--死亡（通貨25%減）----|
  |                         |--Shop Gate / F2------|
  |                         |                       | 前後Stage Gate→Game再生成
  |                                                 |
  +-------------- Result <--最終Stage初回撃破--------+
```
- Shop：4種の能力購入、照準Rayで操作対象を選ぶ。
- Game：各Stageに敵1体。初回撃破で報酬・次Stage解放。全5Stage。
- Game再生成時はPlayer HP、敵、特殊攻撃Cooldown等を初期化する。
- Result：EnterでTitle。周回継続・死亡Result・直接リトライは現行にはない。

## 8. 戦闘の参照
### Game.Updateの順序
1. Scene遷移要求を消費。
2. Debug要求を消費、F2要求。
3. HP状態判定、死亡処理、低HP警告。
4. GameProgress時間、特殊Cooldown、Flash Timer。
5. 敵攻撃→Player攻撃→Projectile→Animation。
6. 敵撃破・進行→Capture→Gate。
7. 最後にCamera回転・Player移動・Camera位置追従。
### 通常射撃
押下判定 → 攻撃要求 → SE/Flash → Camera空間の銃口をWorldへ変換して視覚弾生成 → Camera中心Rayと敵Sphere → Enemy.TakeDamage → 実Damageを進捗報酬へ。
視覚弾は最大16、速度28、寿命1.2秒。弾の到達を待ってDamageを適用する方式ではない。
### 旧特殊攻撃
解放・Cooldown・戦闘中条件を確認しQ要求。水平距離8以内で銃Damageの3倍。敵は1体なので現行コードは複数敵へ列挙適用する構造ではない。
### 敵攻撃
距離とTimerで結果を返す。特殊優先。通常範囲3、間隔1.2秒。移動・攻撃予兆・怯み・転倒AIはない。
### HP
PlayerHealthは初期化/最大回復/ダメージ/死亡判定。低HP閾値25%。Damage直後の無敵や被弾怯み・回復アイテム管理は未実装。

## 10. 描画・Shader契約
### RenderPass
|Pass|Blend|Depth|Cull|
|---|---|---|---|
|Sky|無効|Test/Write無効|なし|
|Opaque|無効|既定State|背面|
|Transparent|Alpha|Testあり/Writeなし|背面|
|Screen UI|Alpha|Test/Write無効|なし|
Passは自動スコープ復元されない。Rendererがどこまで状態変更するかを呼出順と合わせて確認する。
### 3D
BasicMesh/OBJとも位置+UV。CPUでWorldとView*ProjectionをtransposeしてBufferへ格納。HLSLはmul(位置,行列)。Camera b0、Object b1、Material b2。Texture t0、Sampler s0。
GraphicsConstantsは64/80/32/32/32バイトのサイズassert。Light/PostProcess構造体は存在するが、実際の照明/ポスト処理完成を意味しない。
### 2D
QuadはHudCanvasで仮想座標→画面、HudVSでClip変換。HudBuffer b0は3D用Camera b0とは別契約。
TextもCanvasを使用。MeasureTextは仮想座標単位で返し、DrawText側で画面スケールを適用。
FadeはImGui、通常HUDとTitle/Resultは独自Quad/Text。
### 現行Game.Draw
Sky → OpaqueWorld（敵を含む）→ TransparentWorld → 敵HPバー → HUD状態組立 → 敵の追加Draw → GameHud → Debug UI。
追加の敵Drawを省略せず、現状そのものとして記載する。

## 11. 入力・時間・音声
- Inputはキー前/現状態、MouseMove差分、Captureとフォーカスを管理。ゲーム操作のAction Mapではない。
- Camera Pitchは±89度。Gameの射撃はCamera更新より前。
- GameTimerのTimeScaleは存在するがmainのTimerはSceneに渡されず、新企画のジャスト回避制御は未接続。
- GameProgressの時間加算は現行GameSceneからのみ。Shop/Title/Resultでは加算しない。GameStageClear中もGame.Updateが進めば加算。
- Audioは4 BGM/7 SEを初期読込し、BGMを1 Instanceで切替。パス/音量はcpp定数。

## 13. ビルド設定の現状
- x64 Debug/Release：Windows subsystem、C++20、/utf-8、NOMINMAX、D3D11/DXGI/D3DCompiler/WICリンク。
- Win32：Console等の設定で、x64と同等のinclude/link/shader設定ではない。対応保証はしない。
- 個人絶対includeパスが複数混在。$(ProjectDirSource\)Debugという疑わしい表記がある。
- x64 PreprocessorDefinitionsはNOMINMAXのみで、継承プレースホルダーが明記されていない。_DEBUG等の最終実効値はビルドコマンドで確認する。
- CSOはProjectDir/Shadersへ出力しOutDirへコピー。AssetsコピーがPre/Postに重複。
- DirectXTK targetsはpackages配下をimport。packages.config本文と復元状態は未確認。
