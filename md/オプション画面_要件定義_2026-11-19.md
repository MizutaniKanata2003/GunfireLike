# オプション画面（画面設定）要件定義

作成日: 2026-11-19 JST
状態: **要件定義のみ。実装は後回し**（2026-11-19にユーザーと合意）。α期限（2026-11-26）の必須範囲には入れない。
前提: C2で、描画領域を常に16:9にする方式（方式P）を採用済み。C3で、4:3と21:9の窓でHUDが領域内に収まることを、ユーザーが確認済み。

## 1. 目的

プレイヤーが、ゲームが提供する決まった画面解像度（Screen Resolution）と表示方式（Display Mode）を選べるようにする。窓の大きさを自由に変える操作には依存せず、見た目と視野を一定に保つ。

## 2. 範囲

| 区分 | 内容 |
|---|---|
| 対象 | 画面解像度、表示方式、設定の保存と読込、確認と取り消し、オプション画面の入口（タイトル・ポーズ） |
| 対象外（今回） | 画質の設定（影・品質）、FOVスライダー、音量、入力の割当、フレームレート上限、垂直同期の切替、複数モニターの選択、HDR |
| 将来の候補 | FOVスライダー、音量、垂直同期の切替、3D描画解像度の倍率 |

FOVスライダーは、D8以降の検討項目。方式Pは視野を固定するため、αでは設けない。

## 3. 機能要件

### 3.1 表示方式（DisplayMode）

| 値 | 内容 | 備考 |
|---|---|---|
| ウィンドウ | 枠付きの窓。大きさは選んだ解像度のクライアント領域 | 既定 |
| ボーダーレス | 枠なしで、モニターいっぱいの窓。解像度はデスクトップと同じ | モニターの比率が16:9以外なら、黒帯が出る |
| フルスクリーン | 排他のフルスクリーン。選んだ解像度でモニターへ出力する | 現行のSwapChainの方式で動作する。ただし、5章の課題を参照 |

### 3.2 画面解像度（Screen Resolution）

- **固定の16:9のリストから選ぶ**。案: 1280×720、1600×900、1920×1080、2560×1440。
- 現在のモニターより大きい解像度は、選択肢に出さない（モニターの寸法を取得して絞る）。
- ウィンドウ表示では、選んだ解像度が、クライアント領域の大きさになる（枠の分を含めない）。
- ボーダーレスでは、解像度は選べない（デスクトップの解像度に固定）。表示を無効にし、理由を示す。
- フルスクリーンでは、モニターが対応する解像度だけを選べる。

### 3.3 適用と取り消し

- 「適用」を押した時に、設定を反映する。変更前の設定を一時保存する。
- 画面モードか解像度を変えた場合は、**15秒の確認**を出す。「変更を保持」を押さなければ、変更前の設定へ戻す。15秒の取り消しは、見えない画面になった時に戻れるようにする、一般的な方式。
- 「保持」を押した設定だけを保存する。

### 3.4 保存と読込

- 保存先は、実行ファイルと同じ場所の設定ファイル（例: `Settings/Display.ini`）。形式は、読みやすく、手で直せるテキスト。
- 起動時に読み込む。ファイルがない、または値が不正な場合は、既定（ウィンドウ、1280×720）にする。ログへ警告を出す。
- 保存した解像度が、現在のモニターに合わない場合は、既定へ戻す。

### 3.5 入口

- タイトル画面から開く。ゲーム中は、ポーズ（未実装）から開く。ポーズの実装時に追加する。
- Escapeは、現行ではアプリケーションの終了。オプション画面を開いている間は、「戻る」にする（`main.cpp`の扱いを変える必要がある）。

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| 見た目の一貫 | どの解像度・表示方式でも、描画領域は16:9で、視野とHUDの配置は同じ |
| 安全性 | 適用に失敗した場合は、変更前の設定へ戻し、ゲームを続行できる |
| 負荷 | 設定の変更は、フレームの途中で行わない。フレームの境界で実行する |
| 規約 | 規約3文書に従う。1工程の出力は4ファイル以内 |

## 5. 技術的な課題

| 課題 | 内容 | 方針案 |
|---|---|---|
| SwapChainの方式 | 現行は `DXGI_SWAP_EFFECT_DISCARD`（従来のBlt方式）。Microsoftは、FlipモデルのBorderlessが、排他のフルスクリーンと同等以上であり、排他が必要かを再検討するよう案内している | まず、ボーダーレスを標準にする。フルスクリーン（排他）は、Flipモデル化と一緒に検討する。フェーズIのI2〜I3でGraphicsSystemを触るため、そのときに判断する |
| 排他フルスクリーンの手順 | `SetFullscreenState` の後に、`ResizeBuffers` を呼ぶ必要がある。排他では、Alt-Tabで切替が起きることがある | 切替の手順を `GraphicsSystem` に閉じ込める |
| Resizeの手順 | `main.cpp`の`WM_SIZE`が、`GraphicsSystem::Resize` を呼ぶ。表示方式の切替でも、`WM_SIZE`が発生する | 設定の反映は、窓のスタイル変更とResizeの順序を、1か所で管理する |
| 入力のCapture | マウスのCapture中は、窓の移動・サイズ変更に影響する | オプション画面は、Capture解除中に開く（タイトルは解除済み） |
| ImGui | デバッグUIは、窓全体の座標で描かれる。オプション画面は、デバッグUIとは別に、ゲームのUIで作る | UiLayoutとHudCanvasの方式を使う |

## 6. 構成案

| 部品 | 責務 | 置き場所（案） |
|---|---|---|
| `DisplaySettings` | 表示方式と解像度の値、既定値、検証、保存・読込 | `Framework/Etc` |
| `DisplayController` | 設定をWindow・GraphicsSystemへ反映し、変更前の状態を保持して取り消す | `Framework/DirectX` |
| `OptionsScene` | オプション画面の描画と入力。選択・適用・15秒の確認の表示 | `Scene/OptionsScene` |
| `UiButton` | ボタン・選択肢のUI部品。E3の報酬カードと共通化 | `Scene/Common/UI` |

`UiButton` は、E3（報酬カード）でも使う予定。オプションを先に作る場合は、そちらを先に作る。

## 7. 工程案（実施時の細分化）

| ID | 工程 | 依存 |
|---|---|---|
| J1 | `DisplaySettings`（値・検証・保存と読込）。表示は変えない | なし |
| J2 | `DisplayController`（ウィンドウ・ボーダーレスの切替。Resizeの手順） | J1 |
| J3 | `UiButton`と選択肢の部品 | E3と共通化 |
| J4 | `OptionsScene`（解像度・表示方式の選択、適用、15秒の確認） | J2、J3 |
| J5 | タイトルからの導線、Escapeの扱い、保存の反映、確認 | J4 |
| J6 | フルスクリーン（排他）の追加。Flipモデル化の判断（I3と連携） | J5、I3 |

実施の時期は、Must（A〜G）の完了後。フェーズIとHの間に入れる想定。

## 8. 未決事項

| 項目 | 内容 |
|---|---|
| 解像度のリスト | 1280×720〜2560×1440でよいか。4Kを含めるか |
| フルスクリーン | αの対象に含めるか。ボーダーレスだけにするか |
| 15秒の確認 | 秒数を変えるか。ボーダーレスだけの切替でも出すか |
| 保存先 | 実行ファイルの隣でよいか。`%APPDATA%`にするか |
| 入口 | ポーズ画面の実装時期（F6のRunControllerと連動） |

## 9. 受け入れ基準（実施時）

- 全ての解像度・表示方式で、描画領域が16:9で、HUDと視野が同じ。
- 適用して15秒放置すると、変更前の設定へ戻る。
- 再起動後に、保持した設定が復元される。
- 設定ファイルがない・壊れている場合に、既定で起動する。
- 最小化・復帰、Alt-Tabで、崩れない。
