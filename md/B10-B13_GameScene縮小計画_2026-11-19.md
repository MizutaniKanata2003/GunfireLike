# GameScene 縮小計画（B10〜B13）

作成日: 2026-11-19 JST
工程: B10〜B13（`D7以降_細分化タスク一覧_2026-11-18.md` 第4章への追加工程。B9の後、フェーズCの前）
基準: αブランチ最新。`GameScene.h`（SHA `4cd2260`）はB9出力と同じ構成であることを確認した。
目的: **`GameScene`をライフサイクルと、Scene遷移・他Sceneへの値の受け渡しだけにする。** あわせて、初期化失敗の判定とログを汎用の部品にまとめる。
本書は設計と工程の計画で、コード変更は行わない。

## 1. 背景と方針

ユーザー指示（2026-11-19）:

- 初期化に失敗した時の「判定とログ」は、`GameScene`に書かず、今後も使える汎用のものにする。
- `GameScene`に実装するのは、ライフサイクルのメソッドと、他のSceneへ値を渡すメソッドだけにする。それ以外のメソッドは、別のクラスに実装する。

関連する規約:

- 規約02の13.3: クラスは本体400行以内・メンバー変数15個以内・責務は1つ。Sceneは、進行の切替と各クラスの呼出しの仲介だけを担当する。
- 規約02の13.9: 1ファイル500物理行以内。
- 規約02の2: インデントはスペース2個。タブは使わない。
- 運用ルール（タスク一覧1章）: 1工程の出力は4ファイル以内。挙動を変えない整理では、機能追加を混ぜない。

採用しない案（検討済み）: 送付された`Manager`方式（静的な全オブジェクトのリストと`dynamic_cast`検索、固定dt）は採用しない。時間制御（ヒットストップとスローの2系統の経過時間）、更新順の明示、所有と寿命の明示が崩れるため。`Manager::Update`の削除処理は、`Destroy()`で`delete this`した後に`Uninit()`と`SAFE_DELETE`を呼ぶ形で、解放済みオブジェクトを再操作する危険もある。

### 3.4 更新と描画の順序（維持する）

`GameSession::Update`の順序は、B9と同じにする。

1. F2・F1・F4（`UpdateSceneInput`）。F2なら`e_RETURN_TO_TITLE`を返して終了。
2. デバッグ操作（F3・F5〜F9）。F11なら現在のウェーブを飛ばす。
3. ヒットストップとスローの時間を進め、2種類の経過時間を求める。
4. 確認用の攻撃の判定、敵の怯み・転倒、ウェーブの生成、部屋の進行、出口の開閉。
5. 回復アイテムの間隔、Collision可視化の時間、命中表示、反動のずれ。
6. Capture解除中はここで終了。
7. 視点・プレイヤーの移動 → 出口の通過 → 殴打でのリロードのキャンセル・視野角。
8. プレイヤーの戦闘・射撃 → 敵の更新 → Collision可視化のRay。

`GameSession::Draw`の順序: 3D（床・壁 → 範囲の予告 → 出口 → 敵 → Collisionの線）→ HUD → デバッグUI。

`GameSession::Finalize`の順序: デバッグの参照、射撃、プレイヤー戦闘、敵を先に解除 → 出口・ステージObject・共有Renderer・Collision（`StageController::Uninit`）→ HUD → Collision可視化。敵が共有RendererとCollisionWorldを借用しているため、これらより先に敵を解除する。

## 4. 工程

各工程は、挙動を変えない。出力は4ファイル以内で、全体置換を基本にする。工程の前に、αブランチの実ファイルを再取得する。
