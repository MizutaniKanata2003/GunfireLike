# GunfireLike α版 既知の不具合・未実装の一覧（G3）

作成日: 2026-11-22 JST
基準: αブランチ（F9・G2の確認後）。ユーザーのDebug x64・Release x64での目視確認の報告に基づく。
上位文書: `md/01_企画書.md`、`md/02_α版計画_確定版_2026-11-16.md`、`md/D7以降_細分化タスク一覧_2026-11-18.md`

## 1. 本書の読み方

- 「確認済み」は、ユーザーが実機で確認して報告した項目。AIは実機を動かせないため、静的な読み取りとユーザーの報告だけを根拠にしている。
- 「未確認」は、本書の作成時に、コードも実機の報告も確認していない項目。確認が済むまで、完了とは扱わない。
- 「差分」は、企画書と実装が異なる点。α版の範囲で意図的に省いたものと、後で直す不具合を区別する。

## 3. 企画書との差分（未実装・仕様の違い）

### 3.1 進行・リザルト

| 項目 | 企画書 | 現状 | 区分 |
|---|---|---|---|
| ボスの数と周回 | 3サイクル、ボス3体、3体撃破で周回クリア | 1サイクル、近接型のボス1体で、クリア | α範囲外（意図的） |
| 周回の継続 | クリア後に継続または終了を選ぶ。継続時は引き継ぎ | 結果の画面からタイトルへ戻るだけ | α範囲外 |
| 難易度の上昇 | サイクル2・3と次周回で、敵HP・ダメージ・割合が増加 | なし（全部屋が固定の仮値） | α範囲外 |
| リザルトの表示 | 周回数・ラン累計時間・撃破数・総与ダメージ | 「STAGE CLEAR」と、タイトルへ戻るボタンのみ | 未実装 |
| 時間の計測 | 累計時間を計測し、メニュー等で停止 | 計測していない | 未実装 |
| 死亡時の流れ | リザルトから、リトライまたはタイトル | 結果の画面を経ず、約2秒後に自動でリトライ | 差分 |
| 地形 | 平地・坂・階段 | 平地のみ | α範囲外 |

### 3.2 武器・弾薬

| 項目 | 企画書 | 現状 | 区分 |
|---|---|---|---|
| 武器の種類 | 連射・散弾・単発高威力 | 3種を実装。散弾は6つの弾（ペレット）で、弾ごとに判定 | 実装済み |
| 武器切り替え | ホイール／数字キー | 数字キーのみ | ホイールは未実装 |
| 武器スタッツの確認（Tab） | Tabで表示 | 未確認 | 未確認 |
| 弾薬の系統 | 予備弾薬は系統ごとに管理 | 武器ごとに管理（3武器と3系統が1対1の実装） | 差分（見かけ上は同じ） |
| 敵からのドロップ | 回復は稀にドロップ。弾薬のドロップは未定 | ドロップの有無は、本書の作成時に未確認（通貨での購入は実装済み） | 未確認 |

### 3.3 特殊強化

| 項目 | 企画書 | 現状 | 区分 |
|---|---|---|---|
| 実装した系統 | 9種 | 3種（制圧射撃・回避反撃・殴打追撃） | α範囲（計画書のとおり） |
| 未実装の6種 | 近接射撃・持ち替え攻撃・滑走射撃・離脱装填・蹴撃連鎖・転倒追撃 | なし | α範囲外 |
| 候補の提示 | 異なる3候補から1つ。上限到達は抽選対象外 | 候補が3種のため、常に同じ3枚。上限到達時は、通貨へ置換する実装 | 差分 |

### 3.4 敵・ボス

| 項目 | 企画書 | 現状 | 区分 |
|---|---|---|---|
| 敵の3種 | 接近型・射撃型・範囲攻撃型 | 実装済み。部屋ごとの編成は、全て仮値 | 実装済み |
| ボスの攻撃 | 横薙ぎ・振り下ろし・突進。振り下ろしと突進は方向を確定 | 振り下ろし（近接）と叩きつけ（床の範囲）の2種。横薙ぎと突進はなし | 差分 |
| ボスの怯み | 攻撃蓄積で怯む | 射撃で怯んでも、攻撃も移動も止まらない（仮の決定） | 差分 |
| ボスの転倒 | 転倒しない | 蹴りで転倒する（転倒しない設定になっていない） | 不具合に近い差分 |
| ボスのHP表示 | 企画書に明記なし（F5） | 表示なし（ユーザーの判断で省略） | 省略 |

## 4. 既知の不具合・懸念

### 4.1 提出に関わるもの

| 項目 | 内容 | 対応案 |
|---|---|---|
| 作業ディレクトリ依存 | 画像は `Assets/Textures/UI/...` の相対パスで読む。実行ファイルを単独で起動した時に、Assetsとシェーダー（CSO）が、作業ディレクトリから見える位置にあるか、未確認 | 提出用のフォルダーへ、実行ファイルとAssetsを配置し、VS以外から起動して確認する |
| Debugのログ | `Logger` は、Visual Studioの出力ウィンドウにだけ出す。ファイルには保存しない | 提出後の調査が必要なら、ファイル出力を追加する |

### 4.2 動作・操作

| 項目 | 内容 | 重大度 |
|---|---|---|
| Sceneの切替の停止 | 切替の瞬間に、約40〜65msの停止が起きる（画像・文字の読込）。暗転の間に起きるため、プレイには影響しない。DebugとReleaseで差が小さく、読込が原因と推定 | 低 |
| IMEの無効化 | 半角/全角キーの入力窓を抑えるため、IMEを無効にした。副作用として、デバッグUI（ImGui）に日本語を入力できない | 低（意図的） |
| 弾のばらつきの乱数 | 乱数の初期値が固定（12345）。毎回、同じ並びで散る | 低 |
| 敵どうしの押し離し | 壁際で、敵が震える、または壁へ寄る可能性がある。ユーザーの目視では、問題なし | 低（監視） |
| `Init` の失敗時 | 死亡後のリトライで、新しいSceneの `Init` が失敗すると、旧Sceneが残り、再びリトライを要求し続ける可能性がある。通常は起きない | 低 |
| ボスの位置と壁 | 開始位置（0, 1.5, 12）が壁と重ならないことは、ユーザーの目視で確認済み | 解消 |

### 4.3 コードの品質（フェーズI。未実施）

| 項目 | 内容 |
|---|---|
| ファイルの行数 | `GameSession.cpp` が497行で、上限（500行）に近い。次の機能は、責務を分けてから足す |
| 重複 | `TitleScene` と `ResultScene` の、画像の読込と描画の流れが似ている。敵の移動のループが、3か所（接近型・射撃型・範囲攻撃型）にある |
| 長い関数・引数 | `HudSpriteRenderer::Initialize` と `GraphicsSystem::Init`、`DrawCube` の7引数など。D7以降の計画のフェーズI（I1〜I16）の対象 |
| インデント | 今回の工程で全体置換したファイルは、2スペース（規約）。リポジトリの多くの既存ファイルは、タブ。混在している |
| 警告 | DXGIの「古いスワップ方式」の警告が、Debugで出る。既存の構成を維持している（挙動の変更を混ぜない方針） |

## 5. 仮値の一覧（調整の対象）

数値は全て、企画書で未確定の仮値であり、プレイ確認後に調整する。主な置き場所は次のとおり。

| 区分 | 置き場所 |
|---|---|
| 武器の性能・散弾の弾の数 | `WeaponTable.h` |
| 敵のHP・大きさ（ボス含む） | `EnemyTable.h` |
| 部屋の編成とボスの配置 | `EnemyWaveTable.h` |
| ボスの行動の数値 | `BossController.h`（`BOSS_TABLE`） |
| 戦闘・接触・回復の数値 | `CombatTable.h` |
| 死亡・クリアの待ち時間（2.0秒） | `RunController.h` |
| FPSの基準（30 FPS相当）と、ログの間隔 | `FrameMonitor.h` |
| UIの配置 | `UiLayout.h` |

## 6. 残り時間で行える候補（11/23〜11/26）

優先度の高い順。着手には、ユーザーの合意を要する。

1. 提出用フォルダーでの起動の確認（4.1節）。Must。
2. 結果の画面のBGMを、`PlayResultBgm` へ変更する（`ResultScene.cpp` の1行）。
3. ボスを、転倒しない敵にする（企画書どおり）。
4. 結果の画面へ、クリアタイムなどの表示を足す（企画書のリザルト）。
5. ショップのBGM・効果音の使用状況の確認と、足りない場面への追加。
6. フェーズI（品質改善）。ただし、描画の統一（I2〜I8）は、提出直前には行わない。
